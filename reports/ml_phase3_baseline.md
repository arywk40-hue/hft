# Predictive ML — Phase 3: First Baseline Model

## 1. Data used

This baseline used only the existing model-ready development partitions:

- Training: Days 1–64.
- Validation: Days 80–85.
- Missing gap: Days 65–79; no data was fabricated.
- Holdout Days 86–108: not loaded or accessed by the baseline script.
- Days 109–123: outside scope.

The model-ready dataset contains the existing frozen 197-feature set and the
existing 300-second target. No raw CSV files were read, and no Part 1–4 or
freeze artifact was modified.

## 2. Features and preprocessing

The baseline consumed `results/ml/features/frozen_feature_set.csv` exactly as
generated by ML Phase 0. No feature screen was recomputed and no new feature
hypothesis was introduced.

The frozen-screen caveat remains material:

> Frozen-screen baseline: the feature set was predetermined by the existing
> Part-4 frozen artifact and consumed unchanged. A later experiment will
> perform model-specific feature selection using training days only.

The existing Phase 0 train-only standardization was used. It was fitted on
training rows from Days 1–64 and applied unchanged to validation rows from
Days 80–85. No imputation, clipping, or validation-fitted preprocessing was
used.

## 3. Model specification

The model is a single Ridge regression baseline:

```text
model: Ridge regression
alpha: 1.0
intercept: fitted
solver: deterministic normal equations from day-wise sufficient statistics
target: P(t+300) / P(t) - 1
```

No Elastic Net, hyperparameter search, tree model, neural network, GPU
training, strategy, or backtest was implemented.

## 4. Validation methodology

The model was fitted from the 64 train-day Parquet partitions. Predictions
were generated independently for each of the six validation-day partitions.
Metrics were computed both pooled and separately by validation day. Prediction
and target rows retain exact day/timestamp alignment.

## 8. Limitations

- The validation period contains only six available days.
- The frozen feature screen spans all 70 available development days and was
  not a train-only model-selection fit; it was intentionally consumed without
  modification.
- Negative pooled R² and near-chance directional accuracy do not support a
  trading conclusion.
- No holdout evaluation, hyperparameter tuning, feature reselection,
  backtesting, or strategy construction was performed.
